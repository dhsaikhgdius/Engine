本页是 Director 已交付能力的状态单一事实来源。产品指南说明如何操作，工程记录说明为何这样
设计；如果它们与本页不一致，应先核对下方证据，再在同一个变更中同步更新。

最近核验：**2026-08-25**。

## 状态词汇

- **Implemented** — 产品或受支持控制面中可以到达，并有测试覆盖。
- **Experimental** — 已有实现和可测试契约，但可选安装、硬件、许可证、已记录的集成阻塞或
  尚未稳定的契约使其不能承诺生产级保证。
- **Limited** — 已有实用且经过测试的子集；表格中列出的边界明确不受支持。
- **Planned** — 已有设计或脚手架，但不宣称存在完整的受支持工作流。

本页只使用这四种状态。“Implemented”不表示支持每一种编解码器、格式特性、浏览器或远程部署方式。

## 构建与分层健康度

- `npm run build` 会执行 `tools/scripts/check-build-chunk-budget.mjs`，强制检查非 vendor 应用 chunk
  预算。通过预算不表示拆包已经完成；大型 workspace 与 Agent surface 仍应继续按需加载。
- `tools/scripts/checkServerImportBoundaries.ts` 强制执行浏览器 → TypeScript 控制面 → Python 推理
  的分层。每个临时迁移例外都必须固定 importer、target 和原因；除非替换或收窄旧例外，
  新增例外应视为回归。

## 如何更新本页

只有当工作流可到达、持久化或 artifact 契约已定义，并且聚焦回归测试证明所声明边界时，状态才能
前移。如果受支持路径被移除或证据不再通过，状态必须后退。英文和中文版本必须一起更新。
