This page is the status source of truth for shipped Director capabilities. Product guides
explain workflows; engineering records explain design. When either disagrees with this page,
verify the evidence below and update all three in the same change.

Last verified: **2026-08-25**.

## Status vocabulary

- **Implemented** — reachable in the product or a supported control surface and covered by tests.
- **Experimental** — an implementation and testable contract exist, but optional setup, hardware,
  licensing, a documented integration blocker, or an unstable contract prevents a production guarantee.
- **Limited** — a useful, tested subset exists; the boundary listed here is intentionally unsupported.
- **Planned** — design or scaffolding exists, but no complete supported workflow is claimed.

These are the only status labels used on this page. “Implemented” never means that every codec,
format feature, browser, or remote deployment topology is supported.

## Build and layering health

- `npm run build` enforces the non-vendor application chunk budget in
  `tools/scripts/check-build-chunk-budget.mjs`. Passing the budget does not mean code splitting is finished;
  large workspaces and Agent surfaces should continue to load on demand.
- `tools/scripts/checkServerImportBoundaries.ts` enforces the browser → TypeScript control plane →
  Python inference separation. Every temporary migration exception is an explicit importer/target/reason
  tuple; a new exception is a regression unless it replaces or narrows an existing one.

## Updating this page

A status may move forward only when the workflow is reachable, its persistence or artifact contract
is defined, and a focused regression test proves the advertised boundary. A status must move backward
when a supported path is removed or its evidence no longer passes. Update the English and Chinese
versions together.
