---
title: 程序化建模
description: 使用人与 Agent 共用的确定性 recipe 生成可编辑 blocking 阵列与结构。
---

入口位于 **3D 片场 → 模型库 → 程序化建模**。每次修改参数都会重新计算只读输出计划；只有点击
**应用到片场**后才会改变工程。一次应用只产生一条撤销记录，并保存持久化
`proceduralRecipes`：包含精确操作、来源 ID、输出 ID、适用时的 seed、时间与限制说明。

## 操作类型

| 操作          | 结果                                                  |
| ------------- | ----------------------------------------------------- |
| 线性阵列      | 按精确 XYZ 偏移复制道具或场景模型。                   |
| 环形阵列      | 沿有界圆弧复制，并可保留朝向或设置向内、向外、切向。  |
| 镜像          | 沿 X/Y/Z 平面反射副本；可用负缩放保持几何手性。       |
| 种子散布      | 在区域内确定性变化位置、偏航、高度和缩放。            |
| 楼梯          | 生成可编辑直线台阶块，或带可选支柱的螺旋踏步。        |
| 地形          | 生成 seeded FBM 基本体格子高度场，上限为 12 × 12。    |
| L-system 植物 | 生成有界、确定性的基本体枝干和叶簇脚手架。            |
| 碎裂脚手架    | 生成 seeded blocking 碎片，并可原子删除未锁定源物体。 |

每个输出都带指向 recipe 的 `action` reference binding。复制来源时会保留最多 31 条旧 binding，
再追加程序化来源。单次操作最多输出 256 个物体。删除锁定来源、父子删除冲突、重复 ID、越界参数和
无效资产引用都会拒绝整批操作，不会留下半成品。

## Agent 对等

Workbench 暴露相同的 `apply_procedural` 创作动作，例如：

```jsonc
{
  "action": "apply_procedural", // 应用一条程序化 recipe
  "recipe_id": "hero-crates-v1", // recipe 稳定 ID，写入 proceduralRecipes
  "name": "Hero crate line", // 编辑器里显示的名称
  "created_at": "2026-08-07T01:00:00.000Z", // 创建时间（ISO 8601）
  "operation": { // 具体程序化操作
    "kind": "linear-array", // 线性阵列：按偏移复制
    "sourceObjectId": "crate-hero", // 被复制的来源物体 ID
    "copies": 5, // 复制份数
    "offset": [1.5, 0, 0] // 每份沿 XYZ 的偏移（米）
  }
}
```

UI 预览与 Agent 执行共用同一套校验器和编译器，不存在两套容易漂移的几何实现。

## 支持边界

地形和 L-system 输出是可编辑基本体 blocking，不是焊接后的最终网格；碎裂脚手架不属于 Voronoi
布尔。镜像负缩放可能被下游格式烘焙或拒绝。生产级布尔、连续地形/植被网格、实体化几何导出和
大规模实例化仍属于 DCC/provider 范围，并且必须保留可见损失报告。
