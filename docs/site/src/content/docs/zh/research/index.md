这一整块是面向贡献者的研究与评测材料，不是入门路径。要运行 Director，请从
[快速开始](/zh/getting-started/)进入。

Director 的研究面以证据为中心，不宣称已经冻结的基准、同行评审结果或公开模型排行榜。

## 目标

评估用户或 Agent 是否能完成指定的 3D 制作结果，同时留下可检查、可复现的证据链。

## 任务记录

每个任务都应定义：

- 要求的场景、资产、对象、相机和时间线结果；
- 允许使用的控制面；
- 初始项目或场景修订号；
- 资产与运行时版本；
- turn、调用次数、时间或三者的预算；
- 确定性验收检查；
- 必要时的人类审阅量表；
- 要求保存的 state、trace、audit 和 capture artifact。

## 证据循环

1. 通过声明的接口**观察**初始状态；
2. 通过记录的 UI 或结构化操作**创作**；
3. **校验** schema 和跨实体引用；
4. **审计**空间、时间、结构和相机空间条件；
5. 捕获绑定修订号的图像，或导出项目 artifact；
6. 分开报告自动判断与人类判断。

## 可复现基线

```bash
npm install
npm run dev
npm test
npm run build
```

记录以下信息：

- git 修订或源码快照；
- lockfile hash；
- Node.js 与浏览器版本；
- 任务定义与输入资产；
- system prompt、工具版本和 provider；
- 操作 trace 与预算；
- 最终项目或场景 JSON；
- 校验与审计输出；
- 相机捕获与 artifact hash。

## 报告表

| 字段           | 记录内容                                   |
| -------------- | ------------------------------------------ |
| 任务 ID 与版本 | 不可变任务定义                             |
| 系统版本       | 源码修订、lockfile、运行时                 |
| 控制面         | UI、MCP、HTTP、CLI、浏览器或声明的混合模式 |
| 预算           | 调用、turn、墙钟时间和重试                 |
| 最终状态       | 项目或场景 artifact hash                   |
| 校验           | 通过/失败与详细错误                        |
| 审计           | 结构化问题列表与已应用修复                 |
| 捕获           | 相机 ID、帧、输出路径/hash                 |
| 审阅           | 分开的自动与人类判断                       |

## 发布边界

在任务集、资产、prompt/工具、评测预算、成功标准、审阅协议和报告模板被冻结并版本化之前，不要发布模型比较结果。
