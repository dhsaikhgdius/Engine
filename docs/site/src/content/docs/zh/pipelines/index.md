Director 将布景与生成式渲染分为不同阶段。

## 端到端系统设计

制片管线连接 Canvas 溯源、Stage 表演与 coverage、绑定版本的 Shot Package、DCC/生成任务、Video 剪辑、协作和交换，不会让任何 adapter 变成第二个事实来源。

阅读[管线与系统设计](/zh/pipelines/system-design/)指南。

## 白模到视频

`stage_video` 会将经过验证的场景、当前相机帧、镜头计划、时间线动作、prompt、seed、宽高比、FPS 和时长打包，交给 `vendor/ltx-2` 上的 LTX-2.3 管线。

阅读[白模到视频](/zh/pipelines/video-generation/)指南。

## 职责分离

| Director 负责  | 下游模型负责   |
| -------------- | -------------- |
| 布局和度量尺度 | 外观与纹理合成 |
| 主体放置       | 精细时间细节   |
| 相机和镜头     | 灯光增强       |
| 宽高比和帧范围 | 运动渲染       |
| 结构校验       | 模型特定风格   |
| 参考捕获       | 最终像素生成   |

这样的分离会让几何漂移和相机漂移显性化，而不是把它们藏在一个不透明的生成请求中。

## 标杆制片验收门

端到端标杆案例固定为“双人物公寓对话”。只有同一个项目在不手动导入或导出文件的情况下完成
以下全流程，才算通过：

1. 自然语言 Agent 请求在 `DirectorProject` 中创建房间、贴地人物、初始走位和命名相机。
2. 同一批稳定对象 ID 被 provision 到绑定的 Blender 场景；一次类型化 Blender 事务精修主场景
   几何，并回传求值后的局部 bounds。
3. Director 针对同一批 ID 和最新的项目/原生 revision 调整走位、焦段、相机运动与时间线。
4. 审片截图通过后，选定相机与帧范围输出成片、白模帧、对象 Mask 和米制 Depth。
5. 撤销/重做、审计证据和交付回执始终属于这一个项目；流程中不手动搬运 GLB、`.blend` 或图片。

这个验收门有意跨越多个工作表面。单独一张 Blender 渲染、单独一个 Stage 白模，或一组互不关联的
导出文件都不算通过。

## 产物策略

生成任务产物保存在 `data/` 下：

```text
data/video-jobs/<job_id>/
```

这些是运行时证据，不是手工编写的源文件。

## 当前演进重点

1. 用一个项目级制片图维护跨工作区的身份和溯源。
2. 用一个持久任务状态机管理生成、DCC、代理和转码任务。
3. 使用带明确 promote/use 操作的不可变资产版本。
4. 将已交付的 Blender 回传扩展到光学、灯光、armature 烘焙和 fingerprint 审批，并增加基于 OpenUSD 的 Unreal 交接。
5. 将审批记录绑定到精确的项目和证据 fingerprint。
