## 场景设置

场景检查器控制：

- 全局场景缩放、平移和旋转；
- 天空/背景颜色；
- 全景分配、水平旋转和半径；
- 地面可见性、不透明度和高度；
- 网格吸附与角色标签可见性。

场景变换会作用在所有制片对象之上。应使用它做全局坐标对齐，不要把它当作对象级布景的替代方案。

## 对象类型

Director 项目可以包含：

- 基本体和程序化几何体；
- 开放人形和绑定角色；
- 导入的 GLB、GLTF 和 OBJ 模型；
- 3D 高斯泼溅采集（PLY、SPLAT、KSPLAT、SPZ、SOG）；
- 群体与角色编排；
- 带子对象关系的组；
- 相机 rig 对象；
- 场景资产与绑定。

紧凑的 Stage 协议提供更小的白模词汇：`cube`、`sphere`、`cylinder`、`cone`、`plane`、`torus`、`pyramid`、`humanoid` 以及相机实体。

## 模型库

模型库将内置本地资产与用户导入的模型组合在一起。资产卡片会优先使用已有缩略图，并在用户请求时才生成成本较高的 3D 预览。

### 导入

使用 **导入模型** 导入单个资产，或使用 **导入文件夹** 导入本地集合。除非网关操作明确持久化派生产物，否则导入文件会保留在当前项目/浏览器上下文中。

### 拖放放置

将模型卡片拖入视口。放置位置按以下顺序解析：

1. 指针下有效且可见的模型表面；
2. 配置的场景地面；
3. 根据当前视图推导的备用点。

Director 使用资产的可视边界偏移对象，使渲染后的最低点落在目标表面上。完成世界空间放置后才应用网格吸附。

## 高斯泼溅采集

Director 通过与网格资产相同的 **导入模型** 流程导入 3D 高斯泼溅采集——`.ply`（3DGS 训练输出，含压缩变体）、`.splat`、`.ksplat`、`.spz` 与 `.sog`。泼溅在 Stage 中经 Spark 渲染器渲染，与网格对象按正确深度融合，并包含在截图、clean frame 与视频捕获中。

泼溅采集的行为与普通道具一致：可落地，通过共享的 `realWorldSizeM` 米制归一化缩放，并按采集包围盒选中。采集会从 OpenCV/COLMAP 训练坐标系（Y 向下）烘焙为 Director 的 Y-up 舞台朝向；若某个采集使用不同约定，直接旋转该对象即可。

泼溅没有三角网格。OBJ/STL 导出会在损失报告中以显式原因跳过它们；原生 Blender 交接同样跳过，因为 Blender 没有泼溅导入器。

### 4D 序列

动态（4DGS）采集以一个 `.zip` 导入：内含按播放顺序命名排序的逐帧泼溅文件，以及可选的 `manifest.json`（声明 `fps`，默认 30）。网关解包帧文件后，资产变为 `.4dgs.json` 帧清单。在 Stage 上，序列按 Director 时间轴时钟播放——播放、暂停、拖拽都会定格到对应帧，超出末尾后循环。帧通过有界预载窗口拉取并按最近最少使用淘汰，长序列不会整体载入内存。整个序列的落地与米制归一化以第一帧为锚。

## Blender 原生资产

制片需要原生 mesh、材质、UV、modifier 或 rig 编辑时，从项目根目录运行
`npm run blender`。它启动的是一个集成的 Director 工作流：Director 继续作为导演台，
Blender 负责原生场景内核。这不是第二个 Director 项目，也不需要把每次编辑都走文件导入。

当前 Director 项目绑定到 Blender 后：

1. Director 模型实例只需 provision 一次，就会以同一制片 ID 成为原生根对象；
2. 在 Blender 中创建的原生根对象会作为普通可选对象进入 Director 场景树；
3. 在 Stage 点击原生子对象会选中它所属的 Director 根对象；在场景树选择根对象也会选中对应原生对象；
4. Director 中的移动、旋转、缩放、重命名、可见性、删除和模型放置会通过原生 revision 事务提交，
   再回读到同一个对象；
5. 右侧检查器只显示当前对象的语义属性；Blender 所有的 topology、材质、UV、modifier 与 rig
   细节统一通过顶层 **Blender** 页签检查，不在 Properties 下方重复实现。

场景树刻意只镜像原生**根对象**，不会把每个 Blender 子节点复制成 Director 对象。布景、镜头身份、
相机、时间线和高层角色导演操作留在 Director；topology、Edit Mode 选择、modifier 和原生材质/UV
使用 **Blender**。Director 人物只保留一套 Character 检查器，兼容的 Action/Pose 会转换到原生
armature；原始 Rig 检查器用于不属于 Director 人物的 Blender armature。两边访问的是同一份绑定
场景，不会各自维护竞争的 mesh。

小型原生状态快照只属于 runtime evidence。Stage 与检查器共享同一个 poller 提供的 scene epoch、
revision、帧和选择，不会把快照保存成第二套可编辑项目。所有权规则见
[数据模型](/zh/architecture/data-models/#blender-原生场景绑定)；它与 `.blend` 导入/往返的区别见
[交换格式](/zh/pipelines/interchange/#blender-原生模式不是交换格式)。

## 可视边界与 pivot

导入资产的建模原点经常远离可见几何体。Director 会测量可视边界，并将其用于：

- 落地；
- 选择与取景；
- 变换控件定位；
- 缩略图和预览取景；
- Agent 空间审计。

这样就不必假设文件原点一定是可用的制片 pivot。

## 真实尺寸

模型资产可以声明 `realWorldSizeM`，即以米为单位的真实尺寸，按包围盒最大边测量。Director 会把模型缩放到该尺寸，让道具、载具、建筑与角色共处同一套米制尺度。该数值来自：

- 从模型库加入时按资产类别取的默认尺寸，并对 trees、trains、buildings 等源目录使用更细的默认值；
- Asset Catalog v2 条目自带的 `bounds_m`/`height_m`，优先于类别默认值；
- 道具检查器中的 **真实尺寸** 字段，可覆盖上述任一默认值；清空后资产回到下面的兜底行为。

未声明尺寸的资产沿用旧的显示归一化：把最大边缩放到 2 m。该规则只影响渲染。Director 不再
假设归一化后的模型拥有立方体空间边界：模型首次成功加载时会把精确的归一化局部 bounds 写入
对象，绑定的 Blender 场景则会用求值后的完整层级 bounds 替换它。在任一测量产生前，空间放置
与碰撞检查会明确报告 bounds 未知。

标记 `modelNormalization: "preserve"` 的资产——晋升后的生成 3D 模型或导入的 Blender 场景包——不会被重新适配，保留作者的米制尺度；道具检查器对它们隐藏该字段。

Stage 视口与 OBJ/STL 网格导出使用同一套归一化，导出的道具尺寸与它在 Stage 上的尺寸一致。

## 组与锁定内容

组表示层级，而不是复制几何体。移动组会移动其子对象。Agent 必须保留 `locked: true` 的对象，除非用户明确要求解锁或强制操作。

## 全景背景

将一个资产指定为全景源，然后调整水平旋转和球体半径。启用全景后，编辑器网格仍保持可见；它只属于编辑辅助层，不会进入相机捕获，相机捕获仍使用同一个项目场景状态。

## 角色漫游

选中未锁定的角色，在视口工具栏选择 **角色漫游**。若该角色已有时间线动画，Director 会暂时把其变换交给玩家控制器，退出后恢复常规时间线工作流。编辑器从变换编辑切换到带碰撞的玩家相机；点击视口激活控制，按住鼠标左键拖拽转向，松开左键会结束拖拽但 WASD 仍可继续移动。Director 不会启用 Pointer Lock。点击视口外会释放控制，按 `Esc` 退出模式。退出时，移动会作为一次可撤销的场景编辑提交。

| 控制                     | 动作               |
| ------------------------ | ------------------ |
| `W` `A` `S` `D` / 方向键 | 移动               |
| `Shift`                  | 冲刺               |
| `Space`                  | 跳跃，或飞行时上升 |
| `Ctrl`                   | 飞行时下降         |
| `V`                      | 第一/第三人称视角  |
| `F`                      | 切换飞行           |

漫游时右下角有 **技能施放** 栏（默认开启）。技能占用数字键 `5`–`0` 武装，左键施放、右键取消；`G` 打开上游 VFX 编辑器，`P` 暂停特效时钟，`B` 清除场上效果。这些键不占用上表的漫游跟随按键（含 `Q` `E` `R` `F` `V` `C` 与表情 `1`–`4`）。关掉技能栏后技能热键失效。技能瞄准与粒子、地面贴花、裂隙、动态光、屏幕闪光和相机震动来自 MIT 许可的 [LinearAbiltyCastingThreeJS](https://github.com/achrefelouafi/LinearAbiltyCastingThreeJS)，画在当前片场里，不另开一套渲染器。

这是受 MIT 许可的 [three-player-controller](https://github.com/hh-hang/three-player-controller) 启发的 Director 原生实现：保留现有 R3F 相机、持久化、撤销、时间线与场景协议，而不是引入第二套渲染循环或竞争相机控制器。导航控制与相机 pilot 工作流也参考 MIT 许可的 [3D Director Desk](https://github.com/xiaozangao/3d-director-desk)，并适配 Director 的 Flick 风格舞台、相机模型、帧原生时间线与 Agent 协议。
